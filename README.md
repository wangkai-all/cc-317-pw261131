# 数据平台任务成本分摊与修订追溯（虚构数据演示）

把数据平台的任务成本公平归集到业务产品。多个产品共享同一条上游计算链路，
失败重试、投机执行、业务并行重算都会产生额外用量；本系统在**不重复全额记账、
不抹除未完成用量**的前提下，提供三种可解释分摊方案，并让每份成本报告绑定
**固定证据版**，历史确认结果不可回退。

全部数据（任务图、执行记录、资源账单、消费记录）均为虚构，仅用于演示。
零第三方运行时依赖，仅使用 Python 标准库 + 原生 HTML/CSS/JS。

## 快速开始

```bash
python3 run.py seed                 # 生成三版虚构证据与 9 份报告（幂等）
python3 run.py verify               # 哈希链、可复算性与总额守恒校验
python3 run.py list                 # 查看证据版、报告与状态
python3 run.py serve --port 8000    # 启动网页：http://localhost:8000
python3 -m unittest discover -s tests   # 25 个测试（引擎/存储/API）
```

## 场景与三个证据版

| 版本 | 事件 | 成本总额 |
|---|---|---|
| EV1 | 任务图 v1、14 次尝试封账（3 次失败、2 次投机备份）；服务聚合账单迟到，按标准单价**预提 ¥2.17** | ¥39.68 |
| EV2 | 任务关系追溯更正：补录 `推荐特征加工→经营报表` 需求边；迟到真实账单 ¥2.35 替代预提 | ¥39.86 |
| EV3 | 云厂商修订风控特征账单（¥6.20→¥6.60，旧账单标记替代不删除）；经营分析发起**并行重算**新增 ¥1.55 | ¥41.81 |

关键规则：

- **账单迟到不抹用量**：无真实账单的尝试按标准单价预提，账单到达后替代预提，差额自动进新版；
- **修订不删历史**：被替代账单保留 `SUPERSEDED` 状态与 `supersedes` 链，计价只取有效账单一次；
- **尝试级成本分类**：任务首个成功尝试 = 承诺成本；失败/重试 = 重试额外用量；
  投机备份（含被杀死的）= 投机额外用量；业务发起的重算 = 并行重算用量。
  被杀死的投机与失败尝试资源已占用，账单全额保留。

## 三种分摊方案与公平性取舍

| 方案 | 共享固定成本 | 重试/投机/重算额外用量 | 公平性特征 | 代价 |
|---|---|---|---|---|
| **按资源占用 OCCUPANCY** | 按受益产品需求占比 | 同样按占用结构 | 用量大者多担，口径单一可预测 | 平台基础设施故障的浪费也摊给无辜产品 |
| **边际需求 MARGINAL** | 按 Shapley 在受益产品间**均分**（任一受益方退出都省不下该固定成本，边际贡献相等） | 按占用结构 | 避免大产品交叉补贴小产品 | 小产品在共享任务上承担更多，需业务接受 |
| **因果归责 CAUSAL** | 按占用结构 | 产品侧变更导致的失败/重算**全额归责**；无主基础设施故障进**平台公共成本池**；投机为全体容错按占用分摊 | 责任边界最清晰，适合复盘问责 | 公共池需另行决定吸收或二次分摊，有治理成本 |

三方案**总额严格一致**，差异只在产品与公共池之间的责任分布。网页「方案比较」页
并排展示金额差与适用场景说明。

### 需求权重怎么算

反向拓扑传播：任务的受益产品结构 = 产品对它的直接终端消费 + 各出边通量按下游
产品结构的加权混合，逐层归一化。源头任务因此继承全部下游受益产品；
EV2 补录边会沿图真实改变相关任务的产品占比（测试 `test_08` 固化该行为）。

### 整数守恒

所有金额以**分（整数）**存储，分摊走最大余数法（largest remainder），
每份报告断言：

```
有效账单 + 预提总额  ==  各产品归集 + 公共池  ==  逐尝试行金额之和
```

共享任务在多产品间拆分，任何产品都不会被重复全额计费；差额恒为 0。

## 固定证据版与不可回退

```
data/
├── evidence/EV1.json …      # 证据信封：payload + evidence_hash + 前序哈希
├── reports/RPT-EV3-CAUSAL.json  # 报告：body(含 evidence_hash) + report_hash，写一次
└── ledger.jsonl             # 仅追加哈希链：固化/建报告/确认事件
```

- 报告哈希绑定**证据哈希 + 方案 + 全部计算结果**；`verify` 会用当前证据**重算**
  并比对哈希，任何证据篡改、计算逻辑漂移、守恒破坏都会被发现；
- 报告文件写一次，确认状态只存在于仅追加台账，**没有取消/撤回确认的入口**，
  对已确认报告再次确认返回 `409`；新证据只产生新报告，旧确认的字节与状态不变
  （测试 `test_04_legacy_confirmed_untouched_by_new_version`）；
- 台账每条记录含前一条哈希，篡改任意条目即断链可检测。

## 网页功能

1. **总览与守恒**：KPI（总额/账单/预提/额外用量/公共池）、产品×成本类别归集表、
   方案公平性说明、守恒核对、逐尝试分摊明细（可按类别筛选，每行带分摊去向与中文原因）；
2. **任务图与执行下钻**：SVG 任务 DAG，节点显示任务成本，更正边用虚线标红；
   点击节点查看受益产品、四类成本、每次尝试的账单证据与替代关系；
3. **方案比较与取舍**：同版三方案并排金额、最大-最小差、适用场景卡片；
4. **修订追溯与证据链**：三版时间线与事件、任意两份报告的跨版/跨方案 diff、
   哈希链台账、报告确认操作（确认后按钮消失并标记不可回退）。

## 代码结构

| 文件 | 职责 |
|---|---|
| `costapp/models.py` | 枚举、整数分摊（最大余数法）、规范化 JSON/SHA-256、虚构单价 |
| `costapp/simulator.py` | 确定性生成 EV1–EV3 的任务图、尝试、账单、事件 |
| `costapp/allocator.py` | 账单匹配、尝试分类、需求传播、三方案分摊、守恒断言 |
| `costapp/store.py` | 写一次存储、证据/报告哈希、仅追加台账、完整性校验 |
| `costapp/reports.py` | 证据概览、跨版 diff、演示播种 |
| `costapp/server.py` | 标准库 HTTP：JSON API + 静态页 |
| `web/` | 原生单页应用（无框架、无 CDN） |
| `tests/` | 25 个测试：引擎 10 + 存储 9 + HTTP API 6 |
